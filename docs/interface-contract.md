# Контракт программного интерфейса: запись на кружок

## Выбранная операция

| Поле | Значение |
|---|---|
| Операция | `POST /clubs/{club_id}/join` |
| Назначение | Записать текущего пользователя на кружок |
| Пользовательский сценарий | US-3 — «Запись на кружок и отписка», описан в [спецификации требований](./01-requirements.md) |
| Требование | **FR-3** — студент может записаться на кружок с открытым набором и свободными местами |
| Реализация | [`join_club`](../backend/app/api/clubs.py#L263) |
| Клиентский вызов | [`joinClub`](../frontend/src/api/clubs.ts#L94) |
| Состояние | Реализована |

Операцию вызывает web-клиент от имени вошедшего пользователя, когда студент выбирает действие записи на странице кружка. В локальном Compose API доступен через Nginx по `/api`; без прокси префикс `/api` не используется.

## Вызов

```http
POST /api/clubs/{club_id}/join HTTP/1.1
Host: localhost
Authorization: Bearer <access_token>
Accept: application/json
```

Для запроса непосредственно к backend путь будет `POST /clubs/{club_id}/join` (например, `http://localhost:8000/clubs/101/join`).

Чтобы получить access token, клиент сначала входит через `POST /api/auth/login`, передав JSON с `username` и `password`. В ответе поле `access_token` передаётся в заголовке `Authorization` с префиксом `Bearer`.

### Входные данные

| Данные | Расположение | Тип и ограничения | Обязательно |
|---|---|---|---|
| `club_id` | Параметр пути | Целое число; должен соответствовать существующему кружку | Да |
| Access token | Заголовок `Authorization` | Действующий JWT типа `access`, формат `Bearer <token>` | Да |
| Тело запроса | — | Не передаётся | Нет |
| Query-параметры | — | Не используются | Нет |

Условия успешной записи: пользователь аутентифицирован, имеет право `membership:join`, кружок существует, набор открыт, пользователь ещё не записан и лимит участников не достигнут. Роль `student` имеет это право. По текущей таблице прав такое же разрешение также есть у `admin`; `teacher` не имеет этого права и получит отказ.

## Результат

При успехе сервер создаёт запись членства для текущего пользователя и возвращает HTTP `200 OK`, `Content-Type: application/json`:

```json
{
  "message": "Вы успешно записались на кружок"
}
```

В ответе не возвращаются идентификатор членства или обновлённое количество участников. При необходимости клиент получает актуальное состояние отдельным запросом карточки кружка или профиля.

### Характерная ошибка: набор закрыт

Если у кружка `recruitment_open=false`, членство не создаётся. Сервер возвращает HTTP `400 Bad Request`:

```json
{
  "detail": "Набор в кружок закрыт"
}
```

## Примеры

В примерах `<ACCESS_TOKEN>` нужно заменить действительным access token студента, полученным при входе.

### Успешная запись

Запрос:

```http
POST /api/clubs/101/join HTTP/1.1
Host: localhost
Authorization: Bearer <ACCESS_TOKEN>
Accept: application/json
```

Предполагается, что кружок `101` существует, набор открыт, есть свободное место и студент ещё не состоит в кружке.

Ожидаемый ответ:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"message":"Вы успешно записались на кружок"}
```

### Отказ: набор закрыт

Запрос:

```http
POST /api/clubs/202/join HTTP/1.1
Host: localhost
Authorization: Bearer <ACCESS_TOKEN>
Accept: application/json
```

Предполагается, что кружок `202` существует, но у него закрыт набор. Ожидаемый ответ:

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json

{"detail":"Набор в кружок закрыт"}
```

## Дополнительные ответы реализации

- `401 Unauthorized` — заголовок отсутствует или access token недействителен; тело содержит `detail`.
- `403 Forbidden` — у пользователя нет права `membership:join` (например, роль `teacher`); тело содержит `detail`.
- `404 Not Found` — кружок с указанным `club_id` не найден; тело содержит `{"detail":"Кружок не найден"}`.
- `400 Bad Request` — студент уже записан (`"Вы уже записаны на этот кружок"`) либо достигнут лимит участников (`"Кружок переполнен"`).
