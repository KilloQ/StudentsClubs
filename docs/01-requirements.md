# Спецификация требований

Документ фиксирует исходное понимание функций перед лабораторной работой 2. Сквозные идентификаторы UR/FR/NFR/CR/T вводятся начиная со второй лабораторной работы; в этой исходной версии они намеренно не присваиваются.

## Пользовательские функции

| Пользователь | Функция | Наблюдаемый результат |
|---|---|---|
| Посетитель | Просматривать каталог и карточки кружков | Видит доступные кружки, категории и сведения о занятиях |
| Студент | Зарегистрироваться, войти и выйти | Получает доступ к персональному профилю |
| Студент | Записываться и отписываться от кружков | Состав членства обновляется, результат виден в профиле |
| Студент | Просматривать профиль и посещаемость | Видит членство и связанные данные |
| Преподаватель | Создавать и редактировать собственные кружки | Изменения отображаются в каталоге |
| Преподаватель | Управлять расписанием, участниками и посещаемостью | Сведения доступны в интерфейсе управления |
| Администратор | Управлять пользователями, ролями и категориями | Изменения применяются к каталогу и доступам |
| Пользователь | Просматривать новости/объявления | Видит опубликованные объявления и реакции |

## Нефункциональные ограничения исходного состояния

- UI — одностраничное приложение React; API — HTTP/JSON на FastAPI.
- Backend использует асинхронный SQLAlchemy; локальная инфраструктура контейнеризована.
- Доступ к операциям ограничивается ролью на backend; frontend guards служат дополнением, а не заменой серверной авторизации.
- Файлы хранятся отдельно в S3-compatible хранилище; метаданные — в PostgreSQL.
- Для воспроизводимого локального запуска должны быть доступны Docker Compose и example-настройки без реальных секретов.
- Точные критерии доступности, безопасности, покрытия тестами и производительности будут определены и пронумерованы в ЛР-2.

## Предварительная граница MVP

В основной объём входят аутентификация, каталог, членство, базовое управление кружками и расписанием, учёт посещаемости, профили и административное управление категориями/ролями. Объявления, файлы и погодная интеграция существуют в проекте, но их дальнейшее расширение не считается обязательным без подтверждения требований ЛР-2.
